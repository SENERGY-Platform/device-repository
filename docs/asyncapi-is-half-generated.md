# asyncapi.json is only half generated

## Applies when

Adding or changing a kafka topic and wanting `docs/asyncapi.json` to match. The
file looks generated, is only half generated, and nothing in the build says so
when it goes stale.

**Not this if**: the **REST** documentation. That is swaggo, driven by
`lib/api/doc_gen/gen.go` and regenerated by the Dockerfile's `go generate ./...`
— no manual step, and none of the problems below.

## The generator is a separate Go module

`asyncapi-gen/` has its own `go.mod`, so `go generate ./...` from the repository
root never reaches it — not locally and not in the Dockerfile. It has to be run
from inside that directory:

```
cd asyncapi-gen
go generate ./...
```

Because nothing exercises it in CI, its `go.sum` drifts. Expect a first run to
fail with

```
missing go.sum entry for module providing package github.com/segmentio/kafka-go
```

and to need a `go mod tidy` first. That tidy pulls in the main module's
transitive dependencies; it adds no new direct one.

## The generator emits 2.4.0, the committed file is 3.0.0

The generator writes `asyncapi-gen/asyncapi.json` (gitignored) in AsyncAPI 2.4.0.
`docs/asyncapi.json` is the 3.0.0 conversion, produced **by hand** —
`asyncapi-gen/README.md` points at studio.asyncapi.com, alternatively the
`asyncapi convert` CLI.

The conversion is mechanical: each `channels.<name>.subscribe.message` becomes a
`channels.<name>` with `address` plus a `messages` map, and a matching
`operations.<name>.subscribe` entry with `action: send`; `servers.<name>.url`
becomes `host`; `components` carries over unchanged.

## The file must stay committed

`docs/asyncapi.go` embeds it with `//go:embed asyncapi.json`, so the build breaks
without it. That is why the usual "do not commit generated artifacts" rule does
not apply here.

## Expect changes you did not cause

Because the file is only touched when someone remembers to, it drifts.
Regenerating it in August 2026 for one added topic also brought in a model field
(`attributes` on `ModelsHub`) that had been missing from the committed version
for some time. Diff before committing.

The message shapes come from the command structs in `lib/controller/publisher`,
so a changed struct invalidates this file silently until the path above is rerun.
